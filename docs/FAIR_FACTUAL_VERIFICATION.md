# Feira de Natal: ligação factual da aplicação AFROLOC

Target: `app.afroloc.ao`, Vercel project `dist` (`prj_fCebZ0iMrCsW0R7pH74QkNk81Pgp`). Source starts from the exact previously deployed commit `e24116ce8483612a00afc8aee6b1dc63643e4dd9` in AFROLOC_2026. This release replaces the public simulated screen gallery with a focused fair workflow, retaining the AFROLOC visual identity. Unrelated repository branches and domains are not deployed.

The app authenticates against the same AFROLOC project `ljcxqwjvjgobhisqkujr` and reads canonical `afroloc_records`, retaining the exact code and identifier. It does not manufacture codes, coordinates, people, distances, approvals, signatures or certificates. New addresses are created through the canonical `/identities/create` page; users return and refresh. Placeholder LOCAL codes are excluded.

Fair verification is opt-in per address and does not change the existing 100 m witness policy for unrelated addresses. An official validator must have an active verified contact number, a validator/admin role and a jurisdiction matching the address. Self-validation is forbidden. Residential inspections record the actual address coordinates, owner, housing type and condominium identifier, with actor, evidence and expiry. A condominium is explicitly registered by the official validator, never inferred from arbitrary proximity or free text supplied by a resident.

Witnesses need their own currently valid official AFROLOC residence and inspection. Haversine distance uses stored residential coordinates and must be at most 500 m; a condominium address additionally requires the same verified condominium identifier. Three distinct users must confirm on their own authenticated accounts with a delivered, expiring, single-use SMS code and declaration. Revocation, expiry, changed witness coordinates or revoked validator permissions invalidate eligibility on the next query and block certification.

Only an authorised official can approve after the three valid confirmations. Certification writes canonical validation records and status, plus an audit event. A database trigger prevents bypass through legacy address-update routes for enrolled records and freezes their location/ownership identifiers pending official correction. Existing records are not automatically enrolled, certified or migrated. Existing certified status is shown separately from approval for the fair.

The client never receives service credentials or another person's OTP/phone. The new tables have RLS and service-only privileges; the new endpoint verifies the Auth user and enforces existing MFA. Contact numbers are shown only from verified official configuration matching the user's addresses. Missing contacts, inspections or confirmations remain explicitly pending.

Operational prerequisites: validators must be appointed in the existing official role/contact registry, real residences must be inspected, and actual witnesses must confirm their SMS themselves. Automated tests are local and do not prove real mobile-network delivery or physical residence. A controlled test with a titular, three neighbours and an official validator remains necessary to verify that complete human workflow.

Build: `npm ci && npm run build`. Set the same AFROLOC URL and public key via VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY. Do not add a service-role credential to the frontend.
